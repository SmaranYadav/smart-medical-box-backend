# Deploying Smart Medical Box

The frontend is a static site on Vercel; the Flask API runs on Render and
connects to an external MySQL database. The frontend and backend repositories
are separate.

## Render backend

1. Import the `smart-medical-box-backend` GitHub repository into Render as a
   Blueprint, using the repository root. Render reads `render.yaml` to configure
   the Python web service.
2. Enter the connection details for an externally hosted MySQL database when
   Render requests the service's environment variables:
   - `DB_HOST`
   - `DB_USER`
   - `DB_PASSWORD`
   - `DB_NAME`
   - `DB_PORT`
3. The Flask session secret is generated by Render, and secure session cookies
   are enabled. Do not put database credentials or secrets in source files.
4. On its first successful database connection, the service creates the
   application tables from `schema.sql` if they do not exist. The scheduler
   creates its reminder-log table at startup. Check `/api/health` on the
   generated Render URL.

The database must accept connections from Render. Configure its network access
rules as needed, and use a production database with durable storage. The app
starts without web-push keys, but push subscription and medicine notifications
require `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, and `VAPID_SUBJECT` to be set as
Render environment variables. Keep the private key secret.

The medicine reminder scheduler runs in the web service process. Render's free
web services can spin down when idle, so they are not suitable for dependable,
time-sensitive medicine reminders; use an always-on instance for that
requirement.

## Vercel frontend

1. Import the `smart-medical-box-frontend` repository into Vercel. Use the
   repository root as the project root; no build command is needed.
2. Set the Vercel environment variable `BACKEND_URL` to the Render service's
   public origin (for example, `https://your-api.onrender.com`, without a
   trailing slash).
3. Deploy the frontend. Its `/api/*` requests are proxied through Vercel to
   Render, keeping session cookies same-origin in the browser.

The frontend continues to use `http://127.0.0.1:5000` for local development
when opened from localhost.
